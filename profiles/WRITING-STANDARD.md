# Internal writing and wiki language

## Internal profile content

All profiles must use ASD-STE100 principles for internal English. Apply these
principles to `SOUL.md`, memory notes, custom skills, Kanban cards, comments,
handoffs, and messages between profiles.

- Use short sentences. Put one instruction or idea in each sentence.
- Use the active voice and direct verbs.
- Use one term for one meaning. Avoid synonyms when a clear term already exists.
- Use the ASD-STE100 Dictionary for general words when it is available. Keep
  needed technical terms, product names, identifiers, and quoted source text.
- State who must do an action, what they must do, and any needed condition.
- Keep memory notes factual, brief, dated when useful, and clear without
  private shorthand. Do not save secrets or sensitive credentials in memory.
- Use the same style in profile-to-profile task cards, comments, reports, and
  review handoffs. Keep source quotations in their original language.
- Follow the user's language for messages to the user. The internal English
  rule does not set the language of user-facing replies.

Treat ASD-STE100 as a controlled language with writing rules and a controlled
dictionary. Do not claim that text is fully compliant unless it was checked
against the official specification. See the [official ASD-STE100 site](https://www.asd-ste100.org/).

## Curated wiki content

Write curated wiki page titles, headings, explanations, claims, procedures,
limitations, and open questions in Serbian. Use Serbian Latin script unless the
operator or the existing topic convention requires Cyrillic. Keep source quotes
in their original language. Keep URLs, code, commands, identifiers, product
names, frontmatter keys, and validator-required schema labels unchanged.

Raw captures are not curated wiki pages. Preserve their source text as captured.
